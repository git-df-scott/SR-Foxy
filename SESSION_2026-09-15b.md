## 2. The non-ribbon side is closed, and this session did not reopen it

`research/02` §0 already answers the crux question: there is **no** known

## 3. What was built: the search stack no longer needs Sage

The Dunfield–Gong band search is gated behind
`spherogram.links.bands.search.could_be_strongly_slice`, which needs SnapPy
inside Sage for `Link.signature()` and `exterior().fox_milnor_test()`. Two
sessions in this repository have lost time to that dependency, and this
container could not install `passagemath-standard` at all (repeated read
timeouts from `files.pythonhosted.org`).

`scripts/sagefree_slice_filter.py` replaces it with pure Python + numpy +
sympy:

* all pairwise linking numbers vanish;
* `signature(V + Vᵀ) = 0`, computed exactly over `Q` by congruence
  diagonalisation (Sylvester), `V` from `Link.seifert_matrix()`, which needs no
  Sage;
* `|det(V + Vᵀ)|` a perfect square, free from the same matrix;
* Fox–Milnor on `det(V − tVᵀ)` for one-component links, with a degree cap
  above which the link is kept;
* for multi-component links, the same three tests applied to **each
  component** — every component of a strongly slice link bounds a disk, so each
  is a slice knot. Spherogram's own filter does not do this.

Every test is a necessary condition for strong sliceness, and every failure
path returns `True`. So the replacement can only keep **more** links in the
search than the Sage version, never fewer: negatives remain valid coverage of
their box, and **no ribbon disk can be lost**. Same failure direction as the
existing `_safe_filter` patch in `scripts/teichner_certify.py`.

Signature checked against the tables on `3_1, 4_1, 5_1, 6_1, 6_2, 8_8, 9_46,
10_3, L2a1` — all match.

**Calibration [RESULT].** The filter rediscovers the repository's own
calibration target: the verified ribbon disk of `K_B` (31 crossings, the
0-friend of `K_G`) is found and `verify_ribbon_to_unknot`-verified in **1.3 s**,
against 0.9 s for the Sage stack in `results/KB_calibration_shaken20_bands2.json`.
Controls `6_1, 8_8, 9_46, 10_3` all found and verified; `6_3`, which is not
slice, correctly not found.

## 7. A test that failed calibration and was withdrawn [NEGATIVE RESULT]

To speed the multi-component half of the filter I added two link-level tests:
`|det(L)|/2` a perfect square, and a Torres-corrected Fox–Milnor — divide
`det(V − tVᵀ)` by one factor of `t − 1`, then apply the knot test, on the
grounds that a slice link's multivariable polynomial is `f·f̄` (Kawauchi) and
`Δ_L(t) ≐ (t−1)·Δ_L(t,…,t)` (Torres).

**They failed calibration.** With them installed the search no longer finds the
known, verified ribbon disk of `K_B`: the run stopped terminating early, which
is the signature of a filter rejecting links that lie on a *genuine ribbon
movie*. Something in the chain is wrong — the Torres normalisation, the
Seifert-matrix convention, or the specialisation — and the failure direction is
the fatal one. A filter that can lose a disk can lose a counterexample.

Both are left in `scripts/sagefree_slice_filter.py`, unused, behind a comment
saying they must not be reinstated without re-running
`scripts/kb_band_length_floor.py`. Recording this because it is exactly the
error the campaign's standing cautions exist to catch, and it was caught by the
repository's own calibration discipline rather than by inspection.

## 8. The `L_{3,1}` lane, revived with the figure in hand

`research/22` §3.4 calls building `L_{3,1}` "the highest-value construction on
the board that is not another band search: the only place in the catalog where
a computable ribbon-only obstruction meets an open question." The blocker was
that GST Figure 1 is a picture.

**The picture is now in hand.** arXiv's source package for
[1103.1601](https://arxiv.org/abs/1103.1601) ships the figures as vector PDFs:
`Ln1.pdf` is Figure 1, `sliceknot.pdf` is Figure 2, `Lnk.pdf` is Figure 14, and
`Text.tex` carries the pin labels — the twist boxes are `−1` (left) and `+1`
(right), the spirals are `n strands`. Rendered copies are reproducible with
`pymupdf`.

Two things were verified from the primary source this session:

* **`L_{n,k}` is smoothly slice in the standard `B⁴`**, not merely in a
  homotopy ball. §8: "Since the pictured 4-manifold is actually diffeomorphic
  to a 4-ball [Go1], it follows that `L_{n,k}` is smoothly slice." So the
  Eisermann test has a genuinely slice target.
* **Its ribbon status is open exactly for the cases we want.** §8: "The authors
  do not know whether `L_{n,k}` is ribbon except in the special cases `n = 0,1`
  or `k = 0` or `(n,k) = (2,1)`."

Eisermann's determinant theorem was re-read at
[0802.2287](https://arxiv.org/abs/0802.2287) and is a congruence mod 32, as
`research/02` records — not an equality. The pre-registered test stands
unchanged: **if `L_{3,1}` is ribbon then `det V(L_{3,1}) ≡ 81 ≡ 17 (mod 32)`.**

Transcribing the figure by eye is still the wrong way in, because a
mis-read diagram gives a wrong Jones polynomial and could masquerade as a
violation. So this session instead **ran the repository's own
`scripts/gst_L31_shaken_fission.py`, which had never been run**: it recovers
`L_{3,1}` as a one-band fission of Regina's 48-crossing Figure 2 knot and
accepts only on component genus and fiberedness. Two workers are running, seeds
20260916 (80 diagrams, twists 2, length 7) and 777 (80 diagrams, twists 3,
length 6), against the single-diagram pass whose three candidates were all
rejected.

Diao–Pan–Yan (arXiv:2604.17737) were re-checked as a shortcut and ruled out:
their source package has no PD codes, braid words, isometry signatures or
ancillary data, and the paper states the construction algorithm "will be the
content of another paper".

## 11. Why the sweeps are slow, measured rather than guessed

Profiling the filter on real band output (`K_B`, 485 one-band results at length
2 in 0.5 s): linking numbers and signature are below a millisecond, the
symbolic Fox–Milnor step is 6 ms. **The filter is not the bottleneck.** The
cost is downstream: every link the filter keeps goes through spherogram's
isotopy classification, which builds SnapPy exteriors and runs isometry checks,
seconds apiece. A weaker filter therefore costs time quadratically rather than
linearly, which is the price of dropping Sage's multivariable Fox–Milnor.

A note for whoever tries to win it back: `Link.sublink` silently discards
components that are unknotted *and* unlinked, so the per-component slice test
is real but rarely fires — most one-band offspring have an unknotted component.
The pruning that is actually missing is the multivariable test, and the
one-variable substitute tried here failed calibration (§7).

## 12. The R-link property, implemented [NEW TOOL]

`scripts/r_link_test.py`, controls in
`results/session_2026-09-15b/r_link_test_controls.json`.

Three scripts here — `gst_link_from_band_fission.py`,
`gst_L31_shaken_fission.py`, `verify_L31_candidates.py` — end their scope note
with the same sentence: *a positive still needs the R-link property, 0-surgery
on both components giving `#2(S¹×S²)`*. None of them implements it, and
`MANIFEST.md` carries the same caveat. Without it, an `L_{3,1}` nomination
rests on component invariants, and `research/22` is explicit that a wrong link
would give a wrong Jones polynomial and could masquerade as an Eisermann
violation. So this is the gap between a nomination and an identification, and
it is now closed.

Why it is decisive rather than another screen: a closed orientable 3-manifold
with free `π₁` of rank `n` **is** `#ₙ(S¹×S²)` — Kneser–Milnor splits it into
primes, freeness forces each factor to be `S¹×S²` or simply connected, and
Perelman kills the latter. So "π₁ free of rank n" is not evidence for the
R-link property; it is the property.

The test is two-sided, and every branch is a proof rather than a heuristic:

| verdict | ground |
|---|---|
| `YES` | the 0-filled group reduced to `n` generators and **0 relators** |
| `NO` | `H₁` of the filled manifold is not `Zⁿ` (for 2 components, exactly `lk ≠ 0`) |
| `NO` | the filled manifold is hyperbolic — irreducible, `π₁` not free |
| `NO` | the filled group has the wrong number of homomorphisms to a finite group: a free group of rank `n` has exactly `\|G\|ⁿ`, counted exactly by brute force over generator images |
| `UNKNOWN` | homology passes, not certified hyperbolic, counts match, no presentation reached 0 relators — genuinely inconclusive, **never** a rejection |

Controls, all six as expected: 2- and 3-component unlinks `YES`; Hopf `NO`
(filled `H₁ = 0`); `L6a5` `NO` (`H₁ = Z/2`); Whitehead and `L7a1` `NO` — both
pass homology and are caught by the homomorphism count, which is exactly the
case the first two branches cannot reach.

**Applied to the three standing `L_{3,1}` nominations**
(`results/session_2026-09-15b/L31_nominations_rlink.json`): of the seven stored
candidate links, 49–53 crossings, **three are decisively `NO`** and four are
`UNKNOWN`. Their existing rejection was on component genus and fiberedness;
three of them are now rejected on the defining property as well, independently.

`scripts/gst_L31_rlink_fission.py` supersedes the shaken search and applies
this as the gate — before knot Floer, not after, since the R-link test costs
seconds and `pd_to_hfk` on a 20–40 crossing component costs far more — and
writes the PD code of **every** determinant-9/9 candidate as it is found. The
old script kept PD codes only for passes, which is why the earlier nominations
could not be re-examined when the acceptance test improved. That is now fixed.

## 13. The Jones polynomial, and Eisermann's gate, without Sage [NEW TOOLS]

A blocker found by checking readiness rather than by hitting it: even with
`L_{3,1}` in hand, **the test it exists for could not have been run here.**
`scripts/eisermann_ribbon_link_gate.py` calls `Link.jones_polynomial`, which is
Sage-only. So the one lane in the whole catalog where a computable ribbon-only
obstruction meets an open question was gated twice over — once on the link, and
once on an invariant this container cannot compute.

`scripts/sagefree_jones.py` removes the second gate. `spherogram/links/jones.py`
is already pure Python — a Morse exhaustion of the diagram contracting
Temperley–Lieb elements — and imports exactly two things from Sage:
`LaurentPolynomialRing(ZZ, 'q')` and `PerfectMatching`. Both are small, so this
supplies them and injects them. **The algorithm is unchanged**; only the
coefficient ring and the matching class are swapped.

Validated against spherogram's own doctest values: the bracket of `T(2,3)` and
of the 4-component unlink, `V(8_5)`, and `V(Oⁿ) = (q + 1/q)^(n−1)` for
`n = 2..5`. All exact.

`scripts/sagefree_eisermann.py` then computes `null V(L)` (the order of
vanishing at `q = i`) and `det V(L) = [V(L)/V(Oⁿ)]` at `q = i`, with no
floating point in the verdict: the division is exact polynomial division by
`(q²+1)^(n−1)` after clearing denominators, and the evaluation is over the
Gaussian integers.

Controls reproduce the values already in `research/22` §3.2: unlinks `O², O³,
O⁴` give `null V = n−1` and `det V = 1`; `L2a1, L5a1, L6a1, L6a5, L7a1, L8a21`
all give `null V = 0`; `L9n18` gives `null V = 1`, `det V = 9`.

**One erratum.** `research/22` §3.2 records `det V(L9n19) = 25`. Two
independent routes here — exact division then Gaussian evaluation, and a
truncated series expansion about `q = i` — both give **−7**. Since
`−7 ≡ 25 (mod 32)`, the load-bearing claim is untouched: the
component-determinant product is 1, Theorem 2 demands `≡ 1 (mod 32)`, and both
representatives violate it. Only the integer recorded there is off, by exactly
32. Flagging rather than silently changing it, per this repository's
convention on retractions.

**Net effect: the whole `L_{3,1}` pipeline now runs in this container** —
band fission → R-link gate (§12) → knot Floer component profile → Eisermann
`null V` and `det V` — with every stage calibrated against a known answer. The
only missing input is the link.

## 14. A new lane: manufacture certified non-ribbon LINKS, then hunt for a slice one

This inverts the difficulty that has blocked every knot lane in this
repository, and it is the first thing here that attacks the conjecture from the
non-ribbon side with a computable certificate.

For **knots** there is no computable ribbon-only obstruction at all
(`research/02` §0), so a counterexample needs the hard half — proving
non-ribbonness — and only the easy half, sliceness, is ever in reach. That is
why `K_G` has sat open since March.

For **links** Eisermann's Theorem 1 hands over the hard half for free:

> every `n`-component **ribbon** link satisfies `null V(L) = n − 1`,

so `null V(L) < n − 1` **proves** `L` is not ribbon. Meanwhile a slice link with
`n ≥ 2` has `Δ(L) = 0`, hence `det(L) = 0`, hence `V(L)(i) = 0`, hence
`null V(L) ≥ 1`. For `n = 2` the two meet and nothing can be caught — that is
`research/22` §3.1, and why WS5 was vacuous. **From `n = 3` they separate**, and
the window `1 ≤ null V < n − 1` is exactly the set of links that are certified
non-ribbon while still passing the necessary condition for being slice.

A slice link in that window would be the first slice-not-ribbon object of any
kind.

### The census

`scripts/eisermann_census.py` over `HTLinkExteriors(cusps=3)`, the
Thistlethwaite census of hyperbolic 3-component links to 14 crossings.
`results/session_2026-09-15b/eisermann_census_3cusp.json`:

| stage | count |
|---|---|
| links examined | 34,590 |
| all pairwise linking numbers zero | 2,254 |
| every component a slice knot | 960 |
| `null V = 1` — **certified not ribbon** | **95** |

### Screening the 95 for sliceness

`scripts/slice_screen_links.py` and `scripts/triple_linking.py` apply two
Milnor obstructions, both of which vanish for slice links:

* `[z⁴]∇_L = μ̄(123)²` (Cochran, Invent. Math. 82 (1985)) — validated on the
  Borromean rings, which return exactly `∇ = z⁴`, so `μ̄ = ±1`;
* Sato–Levine `β = μ̄(1122) = [z³]∇` on every 2-component sublink, since every
  sublink of a slice link is slice — validated on the Whitehead link, which
  returns 1.

The sublink test is the sharper one. The smallest census entry, **`L9n27`** — 9
crossings, three unknotted components, all linking numbers zero, `∇_L ≡ 0` so
`μ̄(123) = 0`, and `null V = 1` where ribbon demands 2 — has two Whitehead
sublinks and dies there.

**89 of 95 fall to these two. Six survive:** `L12n1933`, `L14n48413`,
`L14n52589`, `L14n52605`, `L14n52619`, `L14n54478`.

### Killing the six

`scripts/levine_tristram.py`: the signature of `(1−ω)V + (1−ω̄)Vᵀ` vanishes for
slice links at every prime-power root of unity. Controls
(`levine_tristram_controls.json`): zero on all unlinks, on the ribbon knots
`6_1` and `9_46`, and on the Borromean rings (which are caught by `μ̄` instead);
nonzero on Hopf and Whitehead. So it returns zero on everything slice and fires
on things that are not — which is the direction that matters, because a screen
that wrongly cuts would discard a counterexample.

**All six have `max |σ_ω| = 1`. All six are not slice.**

### Result

**Every hyperbolic 3-component link of at most 14 crossings that Eisermann
certifies non-ribbon is provably not slice.** Zero survivors, a complete and
clean negative over that census, and the first exhaustive sweep of this kind in
the repository.

The 4-component census (`HTLinkExteriors(cusps=4)`, 7,463 links) is running
with the window widened to `1 ≤ null V < n − 1 = 3`, which is twice as wide, so
it is not a repeat of the same box.

### Why this is worth keeping even though it found nothing

The pipeline is the point: census → Eisermann non-ribbon certificate → `μ̄(123)`
→ sublink Sato–Levine → Levine–Tristram, every stage calibrated against a known
answer, and it runs end to end without Sage. It takes a link and returns either
"provably not slice" or a live target. Nothing comparable exists for knots, and
nothing comparable existed here for links before today.

**Two survive: `L14n62566` and `L14n63195`.** Both are

* 4-component, 14 crossings, hyperbolic, volume `14.65544950…` (equal, so the
  two are very likely mirrors or mutants of one another);
* identical Jones polynomials, palindromic;
* all pairwise linking numbers zero, all four components unknotted;
* **Brunnian** — every 1-, 2- and 3-component sublink is an unlink. Verified
  through `is_unlink_exterior` on each sublink exterior, **not** through
  `simplify('global')`, because this repository has already lost a published
  claim to `simplify('global')` silently deleting split unknot components
  (`research/23` §8). Brunnian-ness means every Milnor invariant of length ≤ 3
  vanishes automatically;
* `∇_L ≡ 0`;
* every Levine–Tristram signature zero;
* **`null V = 1`, where a ribbon 4-component link requires `null V = 3`.**

So both are **proved not ribbon**, and every classical slice obstruction
computable here vanishes on them.

> **If either `L14n62566` or `L14n63195` is slice, it is the first slice link
> that is not ribbon.**

### The decisive next step, stated precisely

For a Brunnian 4-component link the first Milnor invariant that can be nonzero
is `μ̄(1234)`, and it is an honest integer with no indeterminacy precisely
because all shorter invariants vanish. It vanishes for slice links. **It is not
determined by `∇_L ≡ 0`** — the `n = 3` identity `[z⁴]∇ = μ̄(123)²` has no
proven analogue here, and asserting one would be exactly the kind of
unregistered step `UNFINISHED.md` §5 objects to.

So the state is: not ribbon (proved), sliceness open, and the one computation
that most likely closes it is `μ̄(1234)` by a truncated Magnus expansion of the
longitudes over the Wirtinger presentation. That is a concrete, finite,
self-contained computation on an explicit 14-crossing diagram.

If `μ̄(1234) ≠ 0`, both die and the 4-component census closes as cleanly as the
3-component one. If it vanishes, these two become the best candidates for a
slice non-ribbon object that anyone has, and the next obstruction after that is
Casson–Gordon or a genuine slice-disk argument.

### The asymmetry that makes this the expected outcome

Worth stating plainly, because it governs how much a "surviving candidate"
would ever have been worth. In this pipeline **non-ribbonness is proved and
sliceness is only ever *not excluded*.** A survivor is a link for which every
computable obstruction happens to vanish — which is evidence of nothing, since
the obstructions are far from complete. Turning a survivor into a counterexample
needs sliceness **proved**, by exhibiting disjoint slice disks or by a
4-manifold argument, and no tool here can do that.

That is the same wall as the knot side, mirrored. For knots, sliceness is
provable (`K_G`, via Oliveira-Smith) and non-ribbonness is not. For links,
non-ribbonness is provable (Eisermann) and sliceness is not. GST's `L_{3,1}` is
the only object on the board where **both** halves are within reach — slice by
GST §8 via Gompf, non-ribbon testable by Eisermann Theorem 2 — which is exactly
why `research/22` ranks building it first, and why it stays the target.

## 18. RETRACTION: the `L_{3,1}` fission coverage reported in §17's commit was vacuous

`scripts/gst_L31_rlink_fission.py` screened candidates with
`abs(int(S.determinant()))` inside a `try/except: continue`. **`Link.determinant()`
is Sage-only.** Every call raised `SageNotAvailable`, every candidate was
silently skipped, and `det_9_9` was therefore identically 0 by construction.

So these three numbers are **withdrawn**, not results:

| run | box | reported | actual meaning |
|---|---|---|---|
| `gst_L31_rlink_s3` | twists 2, len 5 | 21,665 bands, 0 det-9/9 | no screening happened |
| `gst_L31_rlink_s4` | twists 2, len 6 | 39,045 bands, 0 det-9/9 | no screening happened |
| `gst_L31_rlink_s5` | twists 2, len 3, 8 diagrams | 26,284 bands, 0 det-9/9 | no screening happened |

The commit message for `e17cc57` states the length-5 box "contains no
nomination for `L_{3,1}` at all". **That claim is false and is retracted here.**
The band and linking-number counts in those files are real; every column to the
right of `linking_zero` is not.

What gave it away was a contradiction with the repository's own record: the
earlier Sage-backed pass found **2** determinant-9/9 nominations among 3,209
bands, while this pass found **0** among 39,045 — a strict superset returning
strictly fewer hits, which is impossible. A negative that disagrees with an
existing positive is worth more than a negative that agrees with expectations.

**Fix.** `link_determinant` now computes `|det(L)| = |V_L(q = i)|` from the
Jones polynomial. The obvious alternative, `|det(V + Vᵀ)|` from a Seifert
matrix, is *also* unusable here: spherogram's Seifert algorithm raises
`ValueError('list.remove(x): x not in list')` on connected sums, and the
components of a band fission of the 48-crossing GST knot are exactly that
shape. The Jones route needs no Seifert surface. Checked against the tables on
`6_1 = 9`, `9_46 = 9`, `3_1 = 3`, `4_1 = 5`, `8_19 = 3`, `L5a1 = 8`,
`L2a1 = 2`, and on the two values this search actually compares against — the
square knot and `V_3 = 8_19 # mirror(8_19)`, both 9 — the two cases where the
Seifert route dies.

The determinant failure path no longer swallows: it records into
`determinant_errors` and the run reports it.

**Lesson, third time tonight.** A Sage-only call inside a broad `except:
continue` turns a search into a machine that prints zeros. The first two catches
were a filter that failed the `K_B` calibration (§7) and a Magnus convention that
satisfied the shuffle relations while violating cyclic symmetry (§16). All three
were caught by a control with a known answer, and none by reading the code.
